# BTAI Intake v1.72.24 — secure pilot runbook

**BTAI Intake baseline:** v1.72.23
**Change target:** v1.72.24
**Document revision:** v1.72.24-staging-runbook.1
**Status:** development — do not deploy to production

## What this release changes

- A record ID alone no longer grants draft access. The browser must retain the matching signed draft-access capability.
- Completion notifications derive the recipient, consent and client metadata from the encrypted server record. Browser-supplied recipients, subject lines, HTML and attachments are ignored.
- Automated report generation and client report delivery are off by default. They require separate explicit environment switches.

## Required preview environment variables

Set these only in the Vercel preview environment. Never commit their values.

```text
BTAI_DRAFT_ACCESS_SECRET=<at least 32 random characters>
SUPABASE_URL=<preview or synthetic-test project URL>
SUPABASE_SECRET_KEY=<server-side secret key>
BTAI_ALLOWED_ORIGINS=<exact preview origin>
```

Optional features remain disabled unless deliberately enabled:

```text
BTAI_ENABLE_AUTOMATED_AI=true
BTAI_ENABLE_CLIENT_REPORT_PACK=true
RESEND_API_KEY=<Resend key>
INTAKE_DIRECT_RECIPIENT=<internal monitored mailbox>
```

## Zero-cost pilot rules

1. Use synthetic identities and a test inbox only.
2. Do not use the production Supabase project for schema changes; no paid database branch is required.
3. Do not enable either automated-report switch until cross-session denial and notification-recipient tests pass.
4. Never place a draft-access capability in a URL, email, analytics event or support ticket.
5. A missing or expired capability must return `403`; it must never fall back to record-ID access.

## Release checks

1. Create a new draft and confirm the browser stores a capability locally.
2. Attempt to load that record with its ID but without the capability: expect `403`.
3. Attempt to use that capability with another record ID: expect `403`.
4. Verify that a completion notification cannot be redirected by changing request-body fields in the browser.
5. Verify that missing stored consent blocks automated generation and notification.
6. Confirm the automated features return a truthful unavailable state while their switches are unset.

No production deployment is authorized by this runbook.
